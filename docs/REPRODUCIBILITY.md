# Reproducibility guide

## Levels of reproduction

1. **Integrity check** verifies file presence, sizes, hashes, Python syntax,
   workbook readability, and the absence of hard-coded drive paths.
2. **Unit/smoke checks** exercise image filtering, numerical evaluation, XLSX
   export, and model loading on a small image.
3. **Example reproduction** reruns all processing stages for the 46.3 m example.
4. **Full-study reproduction** requires the complete dataset of 530 boreholes
   from the Dongzhuang Project. These data are confidential engineering records
   and are not included in the public release. Researchers with a justified
   need may contact the corresponding author to discuss access, subject to
   project and data-owner authorization.

## Exact commands

Run from the repository root:

```bash
python scripts/check_repository.py
python scripts/validate_reference_outputs.py
python -m unittest discover -s tests -v
python scripts/model_smoke_test.py
python scripts/postprocess_smoke_test.py
python Geoborehole.py --device auto --output outputs/example_run
```

The published algorithm uses the NVIDIA CUDA parallel-computing platform
through PyTorch. CUDA accelerates DeepLabV3+ inference and tensor operations and
is the recommended route for full-borehole reproduction. It requires a
compatible NVIDIA GPU, driver, CUDA runtime, and CUDA-enabled PyTorch build.
CPU inference is retained as a portable fallback, but the full 46.3 m example
can be substantially slower. Record the GPU model, driver, CUDA, PyTorch, and
package versions when reporting a reproduction run.

## Expected output inventory

A complete example run creates ten depth-interval files in each stage folder:
0–5, 5–10, 10–15, 15–20, 20–25, 25–30, 30–35, 35–40, 40–45, and 45–46.3 m.
The `result` folder additionally contains ten fracture-parameter workbooks and
one whole-borehole evaluation workbook.

The archived source run contains all 50 stage PNGs and ten segment workbooks,
but not the final whole-borehole workbook. Therefore, the public archive can be
used for stage-by-stage visual comparison, while `borehole_evaluation.xlsx`
must be regenerated by the corrected public pipeline.

## Comparing images

Exact byte equality is expected for copied archived files, but a rerun can
differ slightly across OpenCV, PyTorch, CUDA, and image-codec versions. Compare:

- image dimensions and class-color validity;
- connected-component and fracture counts;
- fracture depths and orientations with justified numerical tolerances;
- the visual locations and classes of the principal fracture traces.

Do not use JPEG conversion for masks because lossy colors invalidate class
labels.

## Known scope limitations

- The training images and label set used to fit the network were not present in
  the supplied folder; the repository contains the trained weights only.
- The public example cannot reproduce aggregate results for the complete
  530-borehole Dongzhuang Project study set. Confidential data may be requested
  from Tuo Li (2021095@hebut.edu.cn), but release is not guaranteed and requires
  the relevant authorization.
- The final report was absent from the archived run and is produced only by the
  corrected code.
- QPI/QAI/CEI are documented as implementation-specific quantities; authors
  should define them explicitly in any manuscript text that retains the labels.

## Release maintenance

- Do not add raw records from the confidential 530-borehole dataset without
  authorization from the data owner.
- Replace provisional citation metadata with the accepted title, DOI, journal,
  volume, pages/article number, and software archive DOI.
- Create a versioned release and archive it with Zenodo or an equivalent
  long-term repository; cite the immutable DOI in the manuscript.
